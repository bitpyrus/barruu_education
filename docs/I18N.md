# Multilingual support

## Locales (`packages/i18n/src/locales.ts`)

| Code | Language | Direction | Status |
|---|---|---|---|
| en | English | ltr | source |
| es | Español | ltr | machine-draft |
| ar | العربية | rtl | machine-draft |

`status` is shown to learners: a banner says machine-drafted languages are not yet reviewed. Only a fluent human
reviewer may set `reviewed`. Spanish and Arabic UI catalogs were AI-drafted to prove the pipeline (Arabic proves
right-to-left layout and complex plurals).

**Which languages ship is an owner decision.** Adding one: locale entry + `messages/<code>.json` (all keys) →
`npm test` checks completeness → translate courses with `/translate`.

## UI strings

- All learner-visible UI text uses `t('key', params)` from `useI18n()` — never hard-coded English.
- Format: a safe ICU subset — `{name}` interpolation and `{count, plural, =0 {…} one {…} other {…}}` with
  `Intl.PluralRules` (so Arabic zero/one/two/few/many/other work). Messages are data, never code.
- Missing keys fall back to English and are logged in development; tests fail if any locale misses a key.
- Numbers: `n(value)` uses `Intl.NumberFormat` for the locale.

## Course content: translation overlays (ADR 0003)

Courses are authored once in English. A translation is an overlay file
`packages/content/src/translations/<locale>/<course-id>.json`:

```json
{ "locale": "es", "contentId": "mathematical-thinking", "status": "machine-draft",
  "strings": { "chapters.0.lessons.0.title": { "text": "¿Qué jardín es más grande?", "source": "Which garden is bigger?" } } }
```

- Only prose fields are translatable (`TRANSLATABLE_KEYS`: title, body, prompt, hints, explanation, feedback,
  options' text, goal, objectives, …). IDs, numbers, answers, configs and goals' numbers are never touched, so
  **assessment is identical in every language** (tested).
- `source` records the English text that was translated. If the English changes, the entry becomes **stale** and
  learners see English until it's re-translated — never an outdated translation.
- `npm run content:check` reports per-locale coverage, stale and orphaned entries (fatal for `reviewed` overlays).

Current coverage: Spanish — *Mathematical Thinking* course metadata, chapter list and lesson 1 (65/160 strings);
everything else falls back to English.

## Right-to-left

`<html dir>` follows the locale. Use logical CSS (`ms-*`, `me-*`, `start-*`, `text-start`) not left/right; flip
directional icons with `rtl:rotate-180`. Maths (KaTeX), grids, graphs and numeric inputs stay LTR (`.ltr-island`,
`dir="ltr"`). Text containers use `dir="auto"` so untranslated English fallback renders correctly inside RTL pages.

## Engine feedback and interactive text

- The engine stays language-free. `checkAnswer` returns `message: { code, params, text }`, and so do
  `evaluateGoals` (`feedback`) and the sorting simulation (`noteCode` and `noteParams`). `text` is the English
  fallback.
- `apps/web/src/feedback.ts` (`formatFeedback`) maps a code to `feedback.<code>` in the catalogs.
  - `goal.metric` also translates the metric (`metric.*`) and the comparison (`op.*`).
  - The code `custom` means author-written text. It is already translated via the course overlay.
- Interactives in `@barruu/ui` call `useUiText()`. The web app's `I18nProvider` wraps the app in a
  `UiTextProvider` with its `t()`. Without a provider the UI falls back to the English defaults in
  `packages/ui/src/uiMessages.ts`. Tests check that these defaults match `en.json` exactly.
- Labels inside interactive `config` (shape and slider labels) are translatable overlay strings. Numbers, ids and
  expressions in configs are never translated.

## Known gaps
- Placement item prompts aren't translated yet (overlays for items).
- Arabic uses system fonts (no bundled Arabic font yet) — bundle Noto Naskh/Sans Arabic for offline consistency.
